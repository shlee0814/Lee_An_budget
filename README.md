# 하루 가계부 — GitHub Pages + Supabase

정적 사이트와 Supabase Auth/Postgres로 두 사람이 하나의 장부를 공유합니다. 로그인한 사용자의 인증된 이메일이 관리자 허용 목록의 두 주소 중 하나여야 읽기·수정할 수 있습니다. 익명 사용자 및 다른 계정은 장부에 접근할 수 없습니다.

## 최초 계정 생성

1. Supabase 프로젝트 → Authentication → Users → Add user → Create new user.
2. 허용 목록에 등록한 두 이메일로 각각 계정을 만들고, 각자 관리할 비밀번호를 지정합니다. Auto Confirm User를 선택해 이메일 인증 상태로 생성합니다. 비밀번호는 저장소나 채팅에 남기지 않습니다.
3. 사이트에서 각자의 이메일·비밀번호로 로그인합니다. 사이트에는 공개 회원가입 버튼이 없습니다.

Auth 계정은 아직 자동 생성하지 않았습니다. Supabase 관리 계정과 가계부 로그인 계정은 별개입니다. 프로젝트 관리자는 Authentication의 이메일 가입 설정에서 신규 가입도 비활성화할 수 있습니다. RLS는 가입 가능 여부와 별개로 허용된 두 주소만 장부에 접근시킵니다.

## 사용

- 입력·수정·삭제·목표·고정 지출은 서버 응답을 받은 후 저장 완료로 표시합니다. 저장 중에는 중복 조작을 막습니다.
- 다른 기기의 기록은 5초마다 확인합니다. 입력 중인 폼은 자동으로 덮어쓰지 않으며, 최신 기록 버튼으로 불러옵니다.
- 동시에 수정하면 서버 버전으로 충돌을 감지합니다. 충돌/통신 실패 시 입력 내용을 복구용 JSON으로 내려받고 최신 서버 기록과 비교하세요. 전체 백업 복원은 두 사람의 장부 전체를 교체합니다. 복구용 백업도 검토 후 필요한 기록을 옮기세요.
- 기존 JSON 백업은 `백업 가져오기`에서 `{state: ...}` 및 상태 객체 형식 모두 지원합니다. `이전 브라우저 기록 가져오기`는 같은 사이트·브라우저에 남아 있는 이전 로컬 기록을 이전합니다. 먼저 서버 장부의 전체 백업을 내려받으세요.
- 오프라인 입력은 지원하지 않습니다. 로그인 세션은 브라우저에 보관하며 장부 전체는 서버에서 불러옵니다. 이전 버전의 로컬 기록은 이전을 위해 유지됩니다.
- 사진 OCR은 브라우저에서 처리합니다. 인식 결과 중 사용자가 저장한 거래만 서버에 저장합니다.

## 구성 및 관리

- `supabase-config.js`: 공개 프로젝트 URL과 Publishable key. 관리자/service_role/secret 키 금지.
- `supabase-client.js`: Supabase JS SDK **2.57.4**의 UMD 배포본. https://github.com/supabase/supabase-js (MIT).
- `supabase/schema.sql`: 적용된 초기 스키마. 이미 구성된 프로젝트에 다시 실행하지 마세요.
- 두 이메일은 비공개 스키마 `ledger_private.members`의 슬롯 1·2에서 관리자만 변경합니다. 일반 사용자는 목록을 읽거나 수정할 수 없습니다. 따라서 이 테이블의 RLS에는 허용 정책이 없습니다(의도한 전체 차단).
- `shared_ledger`의 SELECT/UPDATE RLS가 매 요청마다 인증된 사용자의 실제 이메일과 인증 상태를 검사합니다. 클라이언트가 보낸 사용자 메타데이터를 사용하지 않습니다.
- 단일 공유 상태 JSON과 버전 비교를 사용합니다. 동시 변경을 자동 병합하지 않습니다. 장부가 매우 커지면 거래별 테이블로 분리할 수 있습니다.

## 확인

로컬 실행: `python -m http.server 8123`

브라우저 회귀 테스트: Playwright가 있는 환경에서 `node tests/shared-ledger.cjs`. 이 테스트는 별도 브라우저 두 개와 모의 서버로 저장·동기화·충돌·실패 복구·이전 백업·로그아웃을 검증합니다. Chromium 실행 경로는 환경에 맞게 수정하세요. 실제 Supabase 계정의 로그인/쓰기 통합 확인은 계정 생성 후 진행해야 합니다.

배포: GitHub Pages `main` 브랜치의 루트. 빌드 과정이 없습니다.

## UI 개발

월별·카테고리 차트는 React/Recharts, 아이콘은 Lucide, 차트 카드와 버튼은 shadcn/ui 패턴 및 Tailwind CSS를 사용합니다. 기존 화면의 폼과 달력은 HTML 입력 요소와 공통 스타일을 사용합니다. UI를 수정한 뒤 `npm ci && npm run build`를 실행하고 `dashboard.bundle.js` 및 `tailwind.generated.css`를 함께 커밋하세요. GitHub Pages에서는 별도 서버 빌드 없이 번들 파일을 사용합니다.
